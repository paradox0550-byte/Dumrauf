# Спецификация доступа и будущей монетизации

**Статус:** требования к backend. Не означает, что авторизация или платежи уже реализованы.

## 1. Режим запуска
- Приложение работает бесплатно.
- Не требовать оплату, карту или платёжные реквизиты для входа.
- Не создавать активную подписку по умолчанию.
- Платёжные маршруты должны быть выключены feature flag до отдельного запуска.

## 2. Роли и первичный администратор
- Единственный bootstrap super-admin: `paradox0550@gmail.com`.
- Роль super-admin назначается серверной конфигурацией/миграцией, а не пользовательским запросом или параметром формы.
- Нельзя позволять обычному пользователю повысить себе роль, удалить или заблокировать bootstrap super-admin.
- Для супер-администратора обязательны MFA, защищённое восстановление и журналирование критичных действий.
- Смена super-admin допускается только отдельной серверной процедурой с подтверждением и аудитом.

## 3. Разрешённые пользователи
- Публичная саморегистрация выключена.
- Доступ предоставляется только email-адресам, предварительно внесённым super-admin в allowlist.
- Приглашение одноразовое, ограниченное по времени и привязанное к нормализованному email.
- Аутентификация — подтверждение владения email одноразовой ссылкой/кодом; пароль не обязателен. Если вводится пароль, хранить только современный password hash, применять лимиты попыток и MFA для администраторов.
- Проверять allowlist на сервере при каждом входе и при обновлении сессии; удаление адреса из allowlist отзывает все активные сессии.
- Не раскрывать, существует ли email в allowlist, в публичных ответах.
- Email allowlist — основной критерий допуска. Геолокация IP ненадёжна (VPN, мобильные сети, ошибочная геобаза) и не должна быть единственным доказательством страны. Если бизнес-правило требует ограничить доступ территорией РФ, реализовать дополнительную настраиваемую проверку с понятной ошибкой и процессом ручного рассмотрения ложных блокировок. Не заявлять, что IP-проверка гарантирует нахождение пользователя в РФ.

## 4. Минимальная модель данных
- users: id, normalized_email (unique), role, status, created_at, invited_by, last_login_at.
- invitations: token_hash, email, expires_at, used_at, created_by.
- sessions: token_hash, user_id, expires_at, revoked_at, created_at.
- audit_log: actor_id, event, target_id, created_at, metadata без секретов и лишних ПДн.
- Не хранить токены приглашений/сессий в открытом виде.

## 5. Будущая подписка и платежи
- Плановая цена: 105 000 RUB за 1 месяц. Значение должно быть конфигурируемым на сервере, храниться в копейках/целых минимальных денежных единицах, валюта RUB.
- Сейчас цена справочная: обязательная оплата выключена, доступ бесплатный.
- Планируемый провайдер — Робокасса. До подключения проверить договор, merchant credentials, тестовый режим, подпись уведомлений, идемпотентность, возвраты, чеки и webhook IP/подпись по актуальной документации провайдера.
- Не принимать цену или статус оплаты от клиента. Сервер создаёт заказ и рассчитывает сумму по тарифу.
- Подписка активируется только после подтверждённого сервером успешного платежа и отдельной явной операции активации.
- До активации подписки возврат возможен по заявленному условию. Платёжный webhook не должен активировать подписку до подтверждения оплаты.
- Самозанятый: Думрауф Александр Сергеевич, ИНН 701741117861; чек формируется через «Мой налог». До запуска оплаты проверить фактический порядок формирования чека и интеграцию/ручной процесс.
- Не включать автопродление без отдельного явного согласия и описания в оферте.

## 6. Обязательные тесты
- super-admin сохраняет роль после миграций и обновлений.
- Нельзя удалить/заблокировать super-admin через обычный admin API.
- Не allowlisted email не может войти даже при валидной ссылке.
- Удаление email из allowlist отзывает сессии.
- Поддельные/повторные/просроченные приглашения отклоняются.
- В режиме FREE_OFFLINE нет маршрута, который требует оплаты.
- Нельзя активировать подписку клиентским запросом или неподписанным webhook.
- Дубли webhook не создают повторных списаний/активаций.
- Сумма платежа берётся только из серверного тарифа.

## 7. Блокирующие условия production
- Нужен репозиторий/код самого приложения и его backend; текущий репозиторий DUMRAUF.RU содержит статический React-сайт и не реализует этот контур.
- Нужны подтверждённая инфраструктура, база данных в требуемой юрисдикции, email-провайдер, secrets manager и проверенные договоры.
- До включения платной подписки нужны утверждённая оферта, политика возвратов и проверка налогового/кассового сценария.
